## 検証（スコープ再OCR・本番API不使用＝Claude Code の Sonnet サブエージェント）
検証セット220件（ターゲット62＋回帰158）を v3.12 で再OCR → 旧予測(v3.11 API)・freee正解と A/B 比較。**さらに v3.11 を同一サブエージェント経路で50件コントロール再OCR** して OCR変動と真回帰を切り分け（★重要な方法論）。

### 結果
- **ターゲット62件: 21件完全修正＋11件部分改善**。宛名誤読→正しい発行者（KITUNE/KITSUNE/moumou/IOBT/ISEDAI/Bar金魚/Shinokita Base → カクヤス/リカマン/ブルータス/公商）、コンビニ誤読（ファミマ/デイリーヤマザキ/ダイソー→セブンイレブン）、ライフ縦書き、百貨店（クエルボ→ドンキ）。
- **OCR変動フロア=16%**（v3.11同一経路でも元正解の16%が run-to-run で揺れる＝モデル固有ノイズ）。
- **回帰候補25件のうち20件は変動**（v3.11コントロールでも同様に壊れる＝プロンプト無関係）。怖く見えた店名誤り（ローソン→ライフ・佐川→null・ORANGE FIELDS英↔カナ・駐車場運営会社）は**全て既存OCRばらつき**でv3.12起因ではないと確定。
- **真のv3.12回帰は5件のみ・全て confidence 降格**（大和ハウスP/タイムズ24/ダイソー×2/A-PRICE＝store/dateは正しいまま medium→手動確認へ）。**誤ったデータの自動登録は増えない（正しい読みが手動確認に回るだけ＝会計事故ゼロ）**。

### 正味評価
21件完全修正＋11件部分改善（最悪の誤り＝誤った取引先での自動登録を解消）に対し、真のコストは正しい読み5件が手動確認に回るだけ。**明確な net win**。

## ★方法論の学び
プロンプト変更の検証は「新旧の再OCRばらつき」を必ずコントロールで切り分ける。旧予測(API)と新予測(サブエージェント)の直接比較は**経路差＋プロンプト差が混在**する。同一経路で旧プロンプトをコントロール再OCR し変動フロア（今回16%）を測ってから真回帰を判定する。これをしないと既存OCRノイズを「回帰」と誤認して過剰に手を入れる。
